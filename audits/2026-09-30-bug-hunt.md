# Repository bug hunt — September 30, 2026

Completed after the backward-compatibility gate shipped in PR #37.

The targeted review traced device/cloud persistence, asynchronous safety copies,
Restore and Reset, JSON replacement, Undo/deletion lineage, account transitions,
cloud generation reads/writes, and PWA startup. This is a bounded review, not a
claim that every possible repository defect has been eliminated.

## Confirmed findings and repairs

1. **Stale destructive action after safety-copy I/O.** Restore and Reset captured
   the board, awaited its backup, then changed whatever board was current. A
   user could close the modal and edit during a slow backup; auth callbacks could
   also change the signed-in account. Restore could revert current values and
   Reset could erase newer work that was absent from its recovery copy. Both
   operations now compare exact current board bytes, backend identity, and user
   before replacing state or adding Undo. A mismatch stops with a visible retry
   explanation; the completed safety copy is retained. Six delayed-backup
   regressions cover both actions and board/account/backend changes. Existing
   success, failure, large-board and recovery tests remain intact.

2. **Test harness returned before durable startup.** The IndexedDB harness waited
   forty event-loop turns and could return null state when hashing/storage was
   slower, making unrelated task operations fail. A delayed real digest
   reproduced this deterministically. The harness now waits for state readiness
   with an explicit five-second deadline and a startup-specific failure. No
   existing behavior assertions were weakened.

The pre-fix run failed all six destructive-action cases and the delayed-startup
case. The exact test diff and observed red evidence are recorded in
`TEST_CHANGE_RATIONALES.json`. No cloud protocol, security rule, or saved-data
schema changes were needed.
