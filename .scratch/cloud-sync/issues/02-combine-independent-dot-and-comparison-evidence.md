## Parent

[Preserve nonconflicting board decisions across cloud sync — #141](https://github.com/emerald-pham/funsidething/issues/141)

## What to build

Retain independent Yes and Dot choices from two devices and apply every distinct
comparison observation to effective learning once. If the phone chooses B over
A and the Mac chooses C over A, both choices must survive in the dotted chain,
ratings, history, durable board, and final cloud board. Overlapping derived
ratings or chain arrays do not make the choices conflict.

Separate comparisons of the same pair, including different answers, remain
useful observations. Resolving the currently displayed choice must not delete
either observation. Retransmission of one action remains one observation.

Extend the durable decision contract established by ticket 1 rather than adding
a second competing sync mechanism. Keep the current ranking algorithm and
neutral automatic placement behavior. This slice returns focused, green commits
to the shared repair; it does not create a separate release or candidate CI run.

## Acceptance criteria

- [ ] Dispatch the actual Yes or Dot actions from the common starting chain A; preserve both B-over-A and C-over-A choices after either publication order, including offline reopening.
- [ ] Both intended dotted tasks remain represented in a valid resulting chain; do not invent a user comparison between B and C merely to reconcile their order.
- [ ] Both comparisons affect effective ratings and derived scanner state. Keeping both history rows while accepting one branch's learned state is not a pass.
- [ ] Retain two deliberate comparisons of the same pair as separate evidence, including matching and different answers. Repeated delivery, duplicate revision hints, and retried publication of one action do not train it twice.
- [ ] Derive the same valid board and learned result from the same retained decision set regardless of message delivery order, while preserving explicit action context and dependencies.
- [ ] Preserve the valid learned baseline and historical observations without replaying incomplete old history as new training. Unknown comparison formats remain protected evidence.
- [ ] Automatic first placement and ordinary navigation remain neutral where the current product requires it; eligibility, completion, and existing scan-day rules remain intact.
- [ ] Verify visible chain, effective ratings, history, durable saved result, and exact cloud content through the approved complete-app boundary with observed RED followed by GREEN.
